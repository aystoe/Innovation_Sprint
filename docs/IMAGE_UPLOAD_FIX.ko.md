# 이미지 선택·기본 이미지 처리 변경

- 행사 생성 폼의 기본 이미지 프리뷰를 제거했다. 사용자가 선택한 사진만 프리뷰에 표시한다.
- 사용자 이미지 없이 Publish하면 번들에 있는 기본 JPEG를 읽어 작성자 소유 경로의 event-images Storage에 업로드한다.
- 사용자 이미지가 있으면 해당 이미지가 우선하며 기본 파일을 함께 업로드하지 않는다.
- 기본 이미지 파일명은 default-UUID.jpg로 저장해 수정 화면에서도 기본 프리뷰를 숨긴다. DB 컬럼 추가는 필요 없다.
- 기본 이미지가 있는 행사의 내용만 수정할 때는 기존 파일을 재사용한다. 사용자 사진을 제거하면 저장 시 기본 이미지로 교체한다.
- 원본 파일은 object URL로 읽어 큰 원본 base64 복사본을 줄이고 1200px JPEG로 압축한다. 지원하지 않는 형식·5 MiB 초과·손상 이미지·처리 불가·시간 초과를 오류로 처리한다.
- 렌더링 예외가 생기면 빈 화면 대신 재시도 안내를 표시하고 브라우저 Console에 오류를 남긴다.

흰 화면의 원인을 실제 배포 브라우저 Console 로그로 재현·확정하지는 못했다. 이번 변경은 이미지 처리 경로와 렌더링 실패 복구를 보완한 것이다. 특정 기기에서 계속 발생하면 F12 → Console의 첫 빨간 오류를 확인해야 한다.

적용: 기존 프로젝트의 변경 소스를 반영 → Git push → Vercel 배포 완료 → 브라우저 새로고침. 이 ZIP은 실제 .env.local, 기존 중첩 ZIP, 빌드 산출물을 제외한다. PC의 기존 .env.local은 보관한다.

Supabase에는 avatars/event-images 버킷 및 기존 Storage RLS가 적용되어 있어야 한다. 버킷을 Public으로 바꾸지 않는다. 이 코드 변경만으로 원격 버킷이 생성되지는 않는다.

수동 확인:

1. Event image는 빈 상태로 시작한다.
2. 사진을 선택하면 사용자 사진만 보인다. 손상 파일을 선택해도 기존 선택 사진은 유지하고 오류를 표시한다.
3. 사진 없이 Publish하면 event-images에 default- 파일이 저장되고 카드/상세에 기본 이미지가 나온다.
4. 사용자 사진으로 Publish하면 해당 사진이 저장된다.
5. 기본 이미지 행사 Edit 시 프리뷰는 비어 있으며 내용만 수정해도 파일이 늘지 않는다.
6. 사용자 사진 제거 → Save 시 기본 이미지로 바뀌고 이전 파일 정리 정책을 유지한다.

Node 단위 테스트와 구문 검사는 실행했으며, 실제 브라우저·원격 Storage 동작은 미검증이다. 전체 빌드는 설치된 TypeScript 도구가 없어 실행하지 못했다.

추가 수정: 파일 선택창을 열기 전부터 화면이 하얘진다는 보고에 따라 visually-hidden file input + label을 제거했다. 실제 button에서 display:none file input을 클릭하며, 선택/취소 후 버튼으로 preventScroll 포커스를 복원한다. 고정 높이/overflow:hidden 화면에서 보이지 않는 input으로 포커스 스크롤이 일어나는 경로를 제거한다. 실제 사용자 브라우저에서 원인이 확정된 것은 아니며 해당 조합을 검증하는 React 테스트는 작성했지만 의존성 미설치로 미실행이다.
